These two JSON files contain 46 candidate expressions for package-text evaluation. `candidates.json` has 25 SpamAssassin expressions and five Rspamd expressions; `second-candidates.json` adds sixteen SpamAssassin expressions. Every candidate has zero default weight and is disabled by default. The library does not load these files automatically.

Definitions retain upstream IDs, source revisions, file hashes, original syntax, input types, conversion notes and match fixtures. Paths for sources and license files are relative to this directory. The original source files and license notices are preserved under `sources/`, including SpamAssassin's NOTICE. Adapted expressions come from Apache-2.0 sources; surrounding source context remains unchanged.

The second batch records lexical references from parent meta rules. Thirteen of its sixteen expressions are components of larger rules, and fifteen come from sandbox sources. The evaluator checks their wording independently; it does not evaluate parent rules, email context, macros, upstream scores or runtime activation. Both JSON files retain their original selection order so expression IDs and output remain reproducible.

Run either file through `go run ./cmd/spam-rules-eval -rules rules/upstream/candidates.json -corpus testdata/corpus/seed/catalog.json`, substituting the second filename to test that batch. The command requires both paths and accepts `-view raw` or `-view normalized`. It rejects duplicate IDs, enabled or weighted candidates, missing provenance, unsupported expressions and failing match fixtures. Ordinary `go test ./...` includes both batches and their corpus tests.

The normalized body view (`html-text-v2`) removes tags, attributes, comments and script/style/template contents, decodes semicolon-terminated HTML entities once, and folds Unicode whitespace. A self-closing script, style or template start tag still opens a suppressed element. Inline tags can split a word without adding a space; block tags and blank lines separate paragraphs. Case is preserved. Raw-markup rules and lexical HTTP, HTTPS and file URLs use their original inputs. Markdown rendering, JSON escape decoding and full email preprocessing are outside these input views.

On the seed, validation and stress catalogues, the first batch matches only quoted spam in the legitimate dataset package. The second batch adds “click here” matches in the Forex advert, MailKit's donation-button text and another quoted spam message. Normalization drops MailKit's attribute text. In the fresh catalogue, the first batch matches the Slimchews advert's money-back claim; the second matches “click here” in both supplement adverts and “transform your life” in Ikigai. Together they match two of four promotional packages, both in the same evaluation group, and none of the four controls. Both batches miss the essay-writing and moving-service adverts and match none of the four documentation controls. These results do not justify enabling a default rule, and the inspected corpus is no longer an unseen evaluation set.
